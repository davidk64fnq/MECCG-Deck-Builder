Companion Rules Tag Set Reference

MECCG Deck Builder utilizes a two-tier database architecture on startup, loading two distinct local files with zero network latency:

  • cards-dc.json (Core Catalog): The official card database containing printed rules statistics (Primary, Alignment, Race, Skills, Mind, Prowess, etc.), originally derived from open Cardnum data with local developer corrections. This file represents the immutable card catalog.
  • Rules_Support_Tags.json (Rules Intelligence Layer): A companion taxonomy dataset authored entirely by the developer. It bridges unstructured card text into queryable taxonomy tags—mapping site automatic attacks, character recruiting bonuses, and home site resolutions so that generic procedural deck rules can generate legal, themed decks automatically.
Pre-Packaged Developer Baseline: All categories, tags, and site resolutions listed in this reference are already completed and pre-packaged. You do not need to run any extractions or tag any cards—the procedural deck generator and filter dropdowns can use these categories immediately upon opening the app.

Where to Store Your Own Custom Tags

If you create your own taxonomy categories or tags using the Tag Manager or Extraction Tools, you have two choices for where to store them:

  • Option 1: Merge into the Auto-Loaded Baseline (Rules_Support_Tags.json): If you want your custom categories to load automatically every time you launch the application, choose Taxonomy > Save Tag Set..., select Rules_Support_Tags.json, and confirm overwrite.
  • Option 2: Save to a Modular Tag File (e.g. Tournament_Hazards.json): If you are creating specialized strategies or sharing tag sets with other players, save them to a standalone .json file. These files will not load automatically on launch; you pull them into your active session on demand via Taxonomy > Load Tag Set... or Taxonomy > Merge Tag Set....

1. Structured Rules Categories & Tags

The following table documents all structured rules categories and representative tags maintained in Rules_Support_Tags.json:

Category Name Purpose & Description Representative Card(s) & Tag Values
Automatic Attack Indexes guardian creature species printed on site cards (or created by site modifications). Differentiates true Dragon lairs from minor Drake sites and maps regional defenses (Orcs, Trolls, Undead, Elves, etc.) for hazard matching and expedition rules.
  • Dancing Spire, The Lonely Mountain → Dragon
  • Carn Dûm, Moria → Orcs; Trolls
  • Barrow-downs, Dead Marshes → Undead
  • Barad-dûr → Orcs; Trolls; Maia
  • Rivendell (Minion) → Elves; Dúnedain
Combat Bonus Flags cards providing direct prowess and/or opponent body reduction against specific creature species.
  • Dwarves with bonuses vs. Orcs → Orcs
  • Nazgûl hunters → Nazgûl
Faction Bonus Character recruiting bonuses granting bonus Direct Influence (+1 or more, typically +1 to +3) when influencing specific named faction cards or species factions. Powers dynamic recruiting in deck generation rules ("Name": "{Leader.Category:Faction Bonus}" or "Race": "{Leader.Category:Faction Bonus}").

Universal Diplomats: Characters with bonuses against any faction (such as Adrazar or Peath) carry the All tag, which acts as a wildcard across all available factions in active sets.
  • Thranduil → Wood-elves
  • Dáin II → Iron Hill Dwarves; Man
  • Gimli → Iron Hill Dwarves; Elf
  • Théoden → Riders of Rohan
  • Adrazar → All; Dúnadan
  • Beregond → Tower Guard of Minas Tirith
Home Region Relational join mapping character home sites directly to the site's geographic territory. Enables deck generators to build regionally cohesive companies (e.g. Eriador, Gondor, Rohan companies) or calculate movement routes.
  • Aragorn II (Rivendell) → Rhudaur
  • Boromir (Minas Tirith) → Anórien
  • Théoden (Edoras) → Rohan
  • Gimli (Blue Mountain Dwarf-hold) → Lindon
  • Robin Smallburrow → The Shire; Arthedain
Resolved Site Over 95% of characters have a specific named location printed as their home site (e.g. Aragorn → Rivendell), which maps 1:1 to a site card's title. Similarly, most Under-deeps sites connect directly to a named surface hold (e.g. Barad-dûr [0]).

For cards with non-specific, dynamic, or regional locations, the Resolved Site tag assigns a concrete site (or semicolon-delimited list of eligible sites).
  • Doeth, Durthak (card text "Home Site: Any Dark-hold") → Barad-dûr; Carn Dûm; Cirith Gorgor; Cirith Ungol; Dol Guldur; Minas Morgul; Urlurtsu Nurn
  • Gandalf (card text "Home Site: Any Haven") → Edhellond; Grey Havens; Lórien; Rivendell
  • Free-hold dynamic characters → Bag End; Beorn's House; Blue Mountain Dwarf-hold; Dol Amroth; Eagles' Eyrie; Edhellond; Edoras; Grey Havens; Iron Hill Dwarf-hold; Lórien; Minas Tirith; Pelargir; Rhosgobel; Rivendell; Thranduil's Halls; Wellinghall

2. Using Companion Categories in Procedural Deck Rules

These companion categories enable rich, declarative deck generation rules:

A. Universal Starting Site Rule (Handling Standard & Dynamic Characters)

{
  "Name": "Leader's Starting Site",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{Leader.Home}"
  },
  "Fallback": {
    "Name": "Dynamic Home Resolution Fallback",
    "Attributes": {
      "Primary": "Site",
      "Name": "{Leader.Category:Resolved Site}"
    }
  }
}
Execution Walkthrough:
  • Standard Characters (Aragorn, Boromir, Frodo): {Leader.Home} resolves to a specific site title (e.g. "Rivendell"). The primary rule finds the site and succeeds; the fallback is skipped.
  • Dynamic Characters (Doeth, Durthak, Gandalf, Orc Captain): {Leader.Home} resolves to a generic description (e.g. "Any Dark-hold"), matching 0 cards. The engine catches the shortfall, triggers the Fallback, and randomly draws one of the legal sites from {Leader.Category:Resolved Site}!

B. Targeted Dragon Lair Expedition

Recruit destination sites specifically guarded by true Dragons without hardcoding site names: 

{
  "Name": "Dragon Lair Destinations",
  "Section": "Sites",
  "Count": 2,
  "Attributes": {
    "Primary": "Site"
  },
  "Categories": {
    "Automatic Attack": "Dragon"
  }
}

C. Regional Themed Recruitment

Recruit backup characters whose home site is located in the same geographic region as the company leader: 

{
  "Name": "Regional Reinforcements",
  "Section": "Pool",
  "Count": 2,
  "Attributes": {
    "Primary": "Character"
  },
  "Categories": {
    "Home Region": "{Leader.Category:Home Region}"
  }
}
