Companion Rules Tag Set Reference

MECCG Deck Builder includes a companion taxonomy file (Rules_Support_Tags.json) that loads automatically on startup (or via Filter > Load/Merge Tag Set...).

Its primary purpose is to enrich the catalog with objective rules data that Cardnum lacks as structured columns—bridging descriptive rules text (such as “Any Dark-hold”), character recruiting bonuses, and site automatic-attack classifications so they can be queried by the procedural deck generation engine.

Viewing Tagged Cards In-App: Rather than consulting a static manual list, you can view the live list of cards tagged in this file at any time right inside the application: in Filter Slot 3 (bottom panel), select Category: Resolved Site, Faction Bonus, or Automatic Attack. The Master List will immediately display all matching cards from your active sets.

1. Category: Resolved Site

Over 95% of characters have a specific named location printed as their home site (e.g. Aragorn → Rivendell), which maps 1:1 to a site card's title. Similarly, most Under-deeps sites connect directly to a named surface hold (e.g. Barad-dûr [0]).

For cards with non-specific, dynamic, or regional locations, the Resolved Site tag assigns a concrete site (or semicolon-delimited list of eligible sites). These fall into three primary archetypes:

2. Category: Faction Bonus

The companion file includes direct influence recruiting bonuses harvested from character card rules text (as demonstrated in the Dynamic Faction Recruitment Worked Example).

Any character with rules granting +2 Direct Influence against a specific faction is tagged with that faction's exact title (e.g. Thranduil → Wood-elves, Dáin II → Iron Hill Dwarves, Théoden → Riders of Rohan). This allows generative rules to recruit matching factions dynamically using "Name": "{Leader.Tag:Faction Bonus}".

3. Category: Automatic Attack

4. Using Companion Tags in Procedural Deck Rules

These companion categories enable rich, declarative deck generation rules:

A. Universal Starting Site Rule (Handling Standard & Dynamic Characters)

{
  "Name": "Leader's Starting Site",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{Leader.Home}"
  },
  "Fallback": {
    "Name": "Dynamic Home Resolution Fallback",
    "Attributes": {
      "Primary": "Site",
      "Name": "{Leader.Tag:Resolved Site}"
    }
  }
}
Execution Walkthrough:
  • Standard Characters (Aragorn, Boromir, Frodo): {Leader.Home} resolves to a specific site title (e.g. "Rivendell"). The primary rule finds the site and succeeds; the fallback is skipped.
  • Dynamic Characters (Alatar, Gandalf, Orc Captain, Minion Trolls): {Leader.Home} resolves to a generic description (e.g. "Any Dark-hold"), matching 0 cards. The engine catches the shortfall, triggers the Fallback, and randomly draws one of the legal sites from {Leader.Tag:Resolved Site}!

B. Targeted Dragon Lair Expedition

Recruit destination sites specifically guarded by true Dragons without hardcoding site names: 

{
  "Name": "Dragon Lair Destinations",
  "Section": "Sites",
  "Count": 2,
  "Attributes": {
    "Primary": "Site"
  },
  "Tags": {
    "Automatic Attack": "Dragon"
  }
}

C. Under-deeps Surface Entrances

Ensure an Under-deeps company includes an appropriate surface entrance: 

{
  "Name": "Under-deeps Surface Entrance",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{DeepSite.Tag:Resolved Site}"
  }
}
