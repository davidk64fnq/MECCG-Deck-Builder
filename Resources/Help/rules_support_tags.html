Companion Rules Tag Set Reference

MECCG Deck Builder utilizes a two-tier database architecture on startup, loading two distinct local files with zero network latency:

  • cards-dc.json (Core Catalog): The official card database containing printed rules statistics (Primary, Alignment, Race, Skills, Mind, Prowess, etc.), with normalized creature species and structured, machine-actionable Home site predicates.
  • Rules_Support_Tags.json (Rules Intelligence Layer): A companion taxonomy dataset authored to bridge unstructured card text into queryable taxonomy tags—mapping site automatic attacks, character recruiting bonuses, and event requirements so that generic procedural deck rules can generate legal, themed decks automatically.
Pre-Packaged Developer Baseline: All categories and tags listed in this reference are already completed and pre-packaged. You do not need to run any extractions or tag any cards—the procedural deck generator and filter dropdowns can use these categories immediately upon opening the app.

Where to Store Your Own Custom Tags

If you create your own taxonomy categories or tags using the Tag Manager or Extraction Tools, you have two choices for where to store them:

  • Option 1: Merge into the Auto-Loaded Baseline (Rules_Support_Tags.json): If you want your custom categories to load automatically every time you launch the application, choose Taxonomy > Save Tag Set..., select Rules_Support_Tags.json, and confirm overwrite.
  • Option 2: Save to a Modular Tag File (e.g. Tournament_Hazards.json): If you are creating specialized strategies or sharing tag sets with other players, save them to a standalone .json file. These files will not load automatically on launch; you pull them into your active session on demand via Taxonomy > Load Tag Set... or Taxonomy > Merge Tag Set....

Role

Classifies the primary game mechanism a card executes. Symmetrical across card alignments—the card's Primary type (Resource vs. Hazard) naturally dictates whether the mechanism aids the company or hinders the opponent:

  • Automatic-attack: Modifies or creates site guardians (Balrog of Moria, Siege).
  • Combat: Modifies combat prowess (The Pale Sword), the number of strikes in an attack (Awaken Denizens), or combat dice rolls such as strike rolls and resulting body checks (Cruel Caradhras).
  • Corruption: Strategic corruption offense or defense—forces corruption checks or burdens on opposing companies (Lure of Power, Despair of the Heart) or heals, mitigates, and removes corruption (Praise to Elbereth). Note: Incidental corruption costs or self-check triggers on powerful resources and items (such as the tapping drawback on Andúril or bearing The One Ring) are drawbacks, not strategic roles.
  • Deck: Interacts with or disrupts deck mechanics—searching the play deck (Lucky Search), retrieving cards from the deck or discard pile (Reforging), shuffling cards into the play deck (Vilya), or shutting down deck and discard searches (Bane of the Ithil-stone).
  • Duration: Extends the life of events in play (The Will of Sauron).
  • Faction: Interacts with faction recruitment (Stone of Erech).
  • Hand: Hand manipulation and card flow—expanding hand size or drawing (Fellowship, Favor of the Valar), scouting an opponent's hand (Mirror of Galadriel), or forcing hand discard (Khamûl the Easterling).
  • Influence: Direct influence and general recruitment modifiers (Return of the King).
  • Item: Retrieves, transfers, protects, or forces the discard/loss of items (Align Palantír, Indûr Dawndeath).
  • Movement: Modifies travel, pathing, or forces company return (Morannon).
  • Protection: Immunizes against effects or attacks (Sacrifice of Form).
  • Quest: Triggers or advances quest conditions (Andúril, Rescue Prisoners).
  • Readiness: In-play status manipulation—tapping, untapping, healing, or removing/returning cards from the table to hand (Adûnaphel, Call of Home).
  • Site: Alters site status or hold types (Witch-king of Angmar, The White Tree).
  • Terrain: Converts region path symbols between hostile and safe.
Site Requirement Consolidates all card-to-site relationships into a single queryable category. Identifies:
  1. The specific site(s) or hold type(s) where a company must be located to play the card (items, allies, factions, and site-phase events), and
  2. The specific site(s) or hold type(s) an event attaches to, targets, or modifies.
Supports specific named sites (e.g. Minas Tirith, Moria), dynamic hold-type predicates (e.g. Site=Dark-hold, Site=Shadow-hold, Site=Free-hold), and regional site filters (e.g. Region=Dagorlad).
  • Rescue Prisoners → Site=Dark-hold; Site=Shadow-hold
  • Bill the Pony → Bree; Rivendell; Bag End
  • The White Tree → Minas Tirith
  • Old Friendship → Site=Free-hold; Site=Border-hold
  • Siege → Site=Border-hold; Site=Free-hold; Site=Ruins & Lairs
  • Balrog of Moria → Moria; Lórien
  • Morannon → Region=Dagorlad
Target Item Identifies specific item classifications, gear keywords, or magical objects that a resource or hazard event requires in company, enhances, transfers, tests, or targets for corruption/theft.
  • Palantír → Align Palantír, Bane of the Ithil-stone
  • Weapon; Armor → Reforging
  • Gold Ring → Test of Form, The Precious
  • Lost Knowledge → Into the Smoking Cone
Target Species Identifies specific biological species or creature races (e.g. Elf, Dúnadan, Nazgûl) that an event or hazard explicitly targets, modifies, or aids. Supports exact species names as well as dynamic exclusion predicates.

Note on Individual Characters: Do not use this category for specific named individuals (such as Aragorn II or Denethor II). Named character requirements are official database properties tracked directly under the Specific attribute (e.g. Specific: Aragorn II on Return of the King).
  • Nazgûl → The Pale Sword
  • Dúnadan → Andúril, the Flame of the West
  • Hobbit → Halfling Strength
  • Race!=Hobbit && Race!=Wizard → Despair of the Heart

2. Using Companion Categories in Procedural Deck Rules

These companion categories enable rich, declarative deck generation rules:

A. Universal Starting Site Rule (Handling Standard & Dynamic Characters)

Because dynamic home rules are modeled directly as predicates in the official Home attribute (e.g. Site=Haven, Site=Dark-hold, Region=Under-deeps && Site!=Dark-hold), a single rule recruits legal starting sites for 100% of characters with zero boilerplate: 

{
  "Name": "Leader's Starting Site",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{Leader.Home}"
  }
}
Execution Walkthrough:
  • Standard Characters (Aragorn, Boromir, Frodo): {Leader.Home} resolves to a specific site title (e.g. "Rivendell"). The rule finds the site and succeeds.
  • Dynamic Characters (Gandalf, Doeth, Crook-legged Orc): {Leader.Home} resolves to the predicate (e.g. Site=Haven, Site=Dark-hold, or Region=Under-deeps && Site!=Dark-hold). The engine evaluates the predicate on the fly and draws randomly from all matching sites in your active expansions!

B. Automated Destination Sites for Quest Events (Site Requirement)

When your deck includes site-specific quest events (such as Rescue Prisoners or The White Tree), capture the event into a variable and draft destination sites dynamically using Site Requirement: 

[
  {
    "Name": "Rescue Prisoners Quest",
    "SaveAs": "RescueQuest",
    "Section": "Resources",
    "Count": 1,
    "Attributes": {
      "Name": "Rescue Prisoners"
    }
  },
  {
    "Name": "Rescue Destination Sites",
    "Section": "Sites",
    "Count": 2,
    "Attributes": {
      "Primary": "Site",
      "Name": "{RescueQuest.Category:Site Requirement}"
    }
  }
]

C. Targeted Dragon Lair Expedition

Recruit destination sites specifically guarded by true Dragons without hardcoding site names: 

{
  "Name": "Dragon Lair Destinations",
  "Section": "Sites",
  "Count": 2,
  "Attributes": {
    "Primary": "Site"
  },
  "Categories": {
    "Automatic Attack": "Dragon"
  }
}

D. Regional Themed Recruitment

Recruit backup characters whose home site is located in the same geographic region as the company leader: 

{
  "Name": "Regional Reinforcements",
  "Section": "Pool",
  "Count": 2,
  "Attributes": {
    "Primary": "Character"
  },
  "Categories": {
    "Home Region": "{Leader.Category:Home Region}"
  }
}

E. Drafting Regional Hazards (Region Requirement)

Draft hazard creatures keyed strictly to a specific geographic region using Region Requirement: 

{
  "Name": "Gorgoroth Guardians",
  "Section": "Hazards",
  "Count": 3,
  "Attributes": {
    "Secondary": "Creature"
  },
  "Categories": {
    "Region Requirement": "Gorgoroth"
  }
}
