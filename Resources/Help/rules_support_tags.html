Companion Rules Tag Set Reference

MECCG Deck Builder utilizes a two-tier database architecture on startup, loading two distinct local files with zero network latency:

  • cards-dc.json (Core Catalog): The official card database containing printed rules statistics (Primary, Alignment, Race, Skills, Mind, Prowess, etc.), with normalized creature species and structured, machine-actionable Home site predicates.
  • Rules_Support_Tags.json (Rules Intelligence Layer): A companion taxonomy dataset authored to bridge unstructured card text into queryable taxonomy tags—mapping site automatic attacks, character recruiting bonuses, and event requirements so that generic procedural deck rules can generate legal, themed decks automatically.
Pre-Packaged Developer Baseline: All categories and tags listed in this reference are already completed and pre-packaged. You do not need to run any extractions or tag any cards—the procedural deck generator and filter dropdowns can use these categories immediately upon opening the app.
Card Examples & Set Conventions: Wherever possible, card examples throughout this guide are drawn from the base premiere set, The Wizards (METW). For gameplay mechanics introduced in subsequent expansions (such as Under-deeps sites introduced in The Dragons or minion/fallen mechanics from The Lidless Eye and The Balrog), the expansion set code is explicitly noted in parentheses (e.g. MEBA).

Where to Store Your Own Custom Tags

If you create your own taxonomy categories or tags using the Tag Manager or Extraction Tools, you have two choices for where to store them:

  • Option 1: Merge into the Auto-Loaded Baseline (Rules_Support_Tags.json): If you want your custom categories to load automatically every time you launch the application, choose Taxonomy > Save Tag Set..., select Rules_Support_Tags.json, and confirm overwrite.
  • Option 2: Save to a Modular Tag File (e.g. Tournament_Hazards.json): If you are creating specialized strategies or sharing tag sets with other players, save them to a standalone .json file. These files will not load automatically on launch; you pull them into your active session on demand via Taxonomy > Load Tag Set... or Taxonomy > Merge Tag Set....

1. Structured Rules Categories & Scopes

To prevent tagging errors and make authoring intuitive, each category targets a distinct functional layer of the card catalog (its card scope). Use the matrix below to identify which category fits the card you are inspecting, or click any category to jump directly to its detailed rules:

Category Name Card Scope (Primary) Primary Purpose & Role
Adjacent Sites Site (Under-deeps) Surface entrances and contiguous Under-deeps connections
Automatic Attack Site Guardian creature species printed on site cards
Combat Bonus Character Character combat bonuses against specific creature species

Faction Bonus Character Direct Influence recruitment bonuses for specific factions

2. Detailed Category Reference

Adjacent Sites

Card Scope: Site (Under-deeps sites only; surface sites remain [Blank])

Records all sites directly accessible from an Under-deeps site—including both surface site entrances and contiguous Under-deeps sites—with passage movement difficulty ratings stripped so they can be matched cleanly as card titles. This enables dynamic Under-deeps movement and expedition rules without hardcoding site pairs.

Representative Example:
  • Blue Mountain Dwarf-hold; Remains of Thangorodrim; The Under-vaults → Connected surface and Under-deeps sites for The Drowning-deeps (MEBA)

Automatic Attack

Card Scope: Site

Indexes guardian creature species printed on site cards using singular terms (e.g. Orc, not Orcs) to align directly with hazard creature race attributes. For sites that allow open attacks (e.g. "opponent may play any creature keyed to Ruins & Lairs" ), site predicates (e.g. Site=Ruins & Lairs) define which hazard creatures can attack there.

Sites vs. Events/Hazards: Automatic Attack is reserved strictly for site cards to record their native guardians. For resource or hazard events that create, modify, or cancel automatic attacks (such as Siege or Balrog of Moria), use Role: Automatic-attack.
Representative Examples:
  • Dragon → Dancing Spire, The Lonely Mountain
  • Orc; Troll → Barad-dûr, Dol Guldur
  • Spider → Ruined Signal Tower
  • Site=Ruins & Lairs; Site=Shadow-hold → Framsburg (METD — dynamic hold predicate)

Combat Bonus

Card Scope: Character

Flags characters providing combat advantages—such as direct prowess bonuses, body/survival bonuses, opponent body reduction, or strike roll modifiers—specifically against targeted creature species.

Characters vs. Non-Characters: Combat Bonus is reserved strictly for characters. For items, weapons, events, or hazards that modify combat or target specific creature types, use Role: Combat (the mechanism) and Target Species (the targeted species).
Representative Examples:
  • Orc → Character prowess/check bonuses on Dáin II and Gimli
  • Nazgûl → Character combat bonuses on Galva and Peath

Environment Stance

Card Scope: Resource • Hazard (Events & Creatures)

Tracks whether a card requires or benefits from Gates of Morning (Light) or Doors of Night (Shadow) being in play. (Items and allies do not use this tag, as environmental conditions only affect events and certain nocturnal creatures.) This supports two primary workflows:

  • Dedicated Strategy (Top-Down): When building a dedicated Gates of Morning or Doors of Night deck, filtering by this category quickly gathers all matching resource events, hazard events, and creatures that support that strategy.
  • Automated Prerequisite Support (Bottom-Up): When procedural deck rules draft cards that depend on day or night, the generator can automatically include Gates of Morning or Doors of Night in the deck so those cards can actually be played.
Stance Values:
  • Gates of Morning → Light-dependent cards (Clear Skies, Sun)
  • Doors of Night → Shadow-dependent cards (Foul Fumes, Shelob, The Will of Sauron)
  • Gates of Morning; Doors of Night → Dual-environment cards (Moon)

Faction Bonus

Card Scope: Character

Character recruiting bonuses that grant bonus Direct Influence (DI) when influencing specific named faction cards or species factions. Powers dynamic faction recruitment in procedural generation templates.

Representative Examples:
  • Wood-elves → Recruited with bonus by Thranduil
  • Iron Hill Dwarves; Man → Recruited with bonus by Dáin II
  • Riders of Rohan → Recruited with bonus by Théoden
  • All; Dúnadan → Universal diplomat wildcard with species affinity (Adrazar)
  • All → Open diplomat wildcard (Peath)

Home Region

Card Scope: Character

A relational join mapping a character's home site directly to the site's geographic territory. Enables deck generators to recruit regionally cohesive starting companies without manual tagging.

Representative Examples:
  • Rhudaur → Derived from Rivendell (Aragorn II)
  • Anórien → Derived from Minas Tirith (Boromir)
  • Rohan → Derived from Edoras (Théoden)

Region Requirement

Card Scope: Hazard • Resource

Consolidates all card-to-region playability constraints and modifications into a single queryable category. Identifies:

  1. Geographic territories required to bring a card into play (e.g. hazard creatures keyed to specific regions), and
  2. Territories an ongoing event explicitly buffs, alters, or affects (e.g. regional combat modifiers or movement path adjustments).
Dual-Mode Best Practice: For cards that function as both regional Creatures and global Events (such as the Nazgûl), only tag the specific regions where they can be played as a creature. This prevents the generator from falsely drafting them as creatures in illegal regions.
Representative Examples:
  • Harondor; Horse Plains; Gorgoroth; Khand → Playable creature territories for Akhôrahil
  • Imlad Morgul; Gorgoroth → Playable creature territories for Shelob
  • Dagorlad; Udûn → Movement path territories modified by Morannon
  • Wold & Foothills; Hollin; Redhorn Gate → Playable creature territories for Balrog of Moria

Region Type

Card Scope: Region • Site

Classifies the terrain symbol printed on region movement cards. Can be propagated down to site cards using the Cross-Card Lookup tool to enable regional terrain filtering (e.g. Region Type=Wilderness).

Printed Terrain Symbols:
  • Wilderness → Anduin Vales, Arthedain, Cardolan, Rhudaur
  • Shadow-land → Ithilien, Dagorlad, Gorgoroth
  • Dark-domain → Udûn, Nurn
  • Free-domain → Shire, Lindon

Role

Card Scope: Resource • Hazard

Classifies the primary tactical game mechanism executed by non-character cards (events, items, hazards, allies). Symmetrical across alignments—the card's Primary type dictates whether the effect aids your company or disrupts the opponent.

Custom Roles: The 15 roles listed below represent the pre-packaged baseline taxonomy shipped in Rules_Support_Tags.json. You can define additional custom roles (such as Scout Support or Nazgûl Hunter) via Taxonomy > Manage Custom Tags... at any time.
Baseline Roles (Pre-packaged Dataset):
  • Automatic-attack — Modifies, cancels, or creates site guardians (Balrog of Moria, Siege)
  • Combat — General combat strength modifiers—prowess, body, strike rolls, or strike counts (The Pale Sword, Awaken Denizens, Cruel Caradhras)
  • Corruption — Strategic corruption offense or defense—forces corruption checks or burdens (Lure of Power, Despair of the Heart) or mitigates and heals corruption (Praise to Elbereth)
  • Deck — Interacts with deck flow—searching the play deck (Lucky Search), graveyard recursion (Reforging), card cycling (Vilya), or search denial (Bane of the Ithil-stone)
  • Duration — Extends the life or duration of active events in play (The Will of Sauron)
  • Faction — Directly aids or modifies faction recruitment (Stone of Erech)
  • Hand — Hand size manipulation and card draw (Fellowship, Favor of the Valar), hand scouting (Mirror of Galadriel), or forced discarding (Khamûl the Easterling)
  • Influence — Modifies general influence or Direct Influence pools (Return of the King)
  • Item — Retrieves, transfers, protects, or forces the discard/theft of items (Align Palantír, Indûr Dawndeath)
  • Movement — Modifies travel, region pathing, or forces company return (Morannon)
  • Protection — Cancels attacks, prevents strikes, or grants immunity to hazards (Sacrifice of Form)
  • Quest — Triggers or advances victory conditions or scenario quests (Andúril, Rescue Prisoners)
  • Readiness — In-play status manipulation—tapping, untapping, healing, or removing/returning cards from the table (Adûnaphel, Call of Home)
  • Site — Alters site status, hold types, or site playability (Witch-king of Angmar, The White Tree)
  • Terrain — Converts region path symbols between hostile and safe

Site Requirement

Card Scope: Resource • Hazard

Consolidates all card-to-site relationships into a single queryable category. Identifies:

  1. The specific site(s) or hold type(s) where a company must be located to play the card (items, allies, factions, and site-phase events), and
  2. The specific site(s) or hold type(s) an event attaches to, targets, or modifies.

Supports specific named sites (e.g. Minas Tirith, Moria), dynamic hold-type predicates (e.g. Site=Dark-hold, Site=Shadow-hold, Site=Free-hold), and regional site filters (e.g. Region=Dagorlad).

Representative Examples:
  • Site=Dark-hold; Site=Shadow-hold → Required play sites for Rescue Prisoners
  • Bree; Rivendell; Bag End → Required play sites for Bill the Pony
  • Minas Tirith → Target attachment site for The White Tree
  • Site=Free-hold; Site=Border-hold → Permitted sites for Old Friendship
  • Site=Border-hold; Site=Free-hold; Site=Ruins & Lairs → Target sites for Siege
  • Moria; Lórien → Target sites for Balrog of Moria
  • Region=Dagorlad → Geographic site restriction for Morannon

Target Item

Card Scope: Resource • Hazard

Identifies specific item classifications, gear keywords, or magical objects that a resource or hazard event requires in company, enhances, transfers, tests, or targets for corruption/theft.

Representative Examples:
  • Palantír → Required in company for Align Palantír and Bane of the Ithil-stone
  • Weapon; Armor → Target item types for Reforging
  • Gold Ring → Required item type for Test of Form and The Precious
  • Lost Knowledge → Required tome/scroll type for Into the Smoking Cone

Target Species

Card Scope: Resource (Weapons, Items, Allies, Events) • Hazard

Identifies specific biological species or creature races (e.g. Elf, Dúnadan, Wizard, Nazgûl, Orc) that an event, weapon, item, ally, or hazard explicitly targets, modifies, or aids. Supports exact species names as well as dynamic exclusion predicates.

Named Characters vs. Species: Do not use this category for specific named individuals (such as Aragorn II). Named character requirements are official database properties tracked directly under the Specific attribute (e.g. Specific: Aragorn II on Return of the King).
Representative Examples:
  • Orc → Weapons targeting Orcs (Glamdring, Orcrist) or allies aiding against Orcs (Beorn)
  • Nazgûl → Weapons or attacks targeting Nazgûl (Dagger of Westernesse, The Pale Sword)
  • Wizard → Targets or requires a Wizard (Sacrifice of Form)
  • Dúnadan → Grants prowess bonuses to Dúnedain (Andúril, the Flame of the West)
  • Hobbit → Grants body protection to Hobbits (Halfling Strength)
  • Race!=Hobbit && Race!=Wizard → Excludes Hobbits and Wizards from corruption check (Despair of the Heart)

3. Using Companion Categories in Procedural Deck Rules

These companion categories enable rich, declarative deck generation rules:

A. Universal Starting Site Rule (Handling Standard & Dynamic Characters)

Because dynamic home rules are modeled directly as predicates in the official Home attribute (e.g. Site=Haven, Site=Dark-hold, Region=Under-deeps && Site!=Dark-hold), a single rule recruits legal starting sites for 100% of characters with zero boilerplate: 

{
  "Name": "Leader's Starting Site",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{Leader.Home}"
  }
}
Execution Walkthrough:
  • Standard Characters (Aragorn, Boromir, Frodo): {Leader.Home} resolves to a specific site title (e.g. "Rivendell"). The rule finds the site and succeeds.
  • Dynamic Characters (Gandalf, Doeth, Crook-legged Orc): {Leader.Home} resolves to the predicate (e.g. Site=Haven, Site=Dark-hold, or Region=Under-deeps && Site!=Dark-hold). The engine evaluates the predicate on the fly and draws randomly from all matching sites in your active expansions!

B. Automated Destination Sites for Quest Events (Site Requirement)

When your deck includes site-specific quest events (such as Rescue Prisoners or The White Tree), capture the event into a variable and draft destination sites dynamically using Site Requirement: 

[
  {
    "Name": "Rescue Prisoners Quest",
    "SaveAs": "RescueQuest",
    "Section": "Resources",
    "Count": 1,
    "Attributes": {
      "Name": "Rescue Prisoners"
    }
  },
  {
    "Name": "Rescue Destination Sites",
    "Section": "Sites",
    "Count": 2,
    "Attributes": {
      "Primary": "Site",
      "Name": "{RescueQuest.Category:Site Requirement}"
    }
  }
]

C. Targeted Dragon Lair Expedition

Recruit destination sites specifically guarded by true Dragons without hardcoding site names: 

{
  "Name": "Dragon Lair Destinations",
  "Section": "Sites",
  "Count": 2,
  "Attributes": {
    "Primary": "Site"
  },
  "Categories": {
    "Automatic Attack": "Dragon"
  }
}

D. Regional Themed Recruitment

Recruit backup characters whose home site is located in the same geographic region as the company leader: 

{
  "Name": "Regional Reinforcements",
  "Section": "Pool",
  "Count": 2,
  "Attributes": {
    "Primary": "Character"
  },
  "Categories": {
    "Home Region": "{Leader.Category:Home Region}"
  }
}

E. Drafting Regional Hazards (Region Requirement)

Draft hazard creatures keyed strictly to a specific geographic region using Region Requirement: 

{
  "Name": "Gorgoroth Guardians",
  "Section": "Hazards",
  "Count": 3,
  "Attributes": {
    "Secondary": "Creature"
  },
  "Categories": {
    "Region Requirement": "Gorgoroth"
  }
}
