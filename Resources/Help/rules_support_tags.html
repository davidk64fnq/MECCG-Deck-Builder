Companion Rules Tag Set Reference

MECCG Deck Builder utilizes a two-tier database architecture on startup, loading two distinct local files with zero network latency:

  • cards-dc.json (Core Catalog): The official card database containing printed rules statistics (Primary, Alignment, Race, Skills, Mind, Prowess, etc.), with normalized creature species and structured, machine-actionable Home site predicates.
  • Rules_Support_Tags.json (Rules Intelligence Layer): A companion taxonomy dataset authored to bridge unstructured card text into queryable taxonomy tags—mapping site automatic attacks, character recruiting bonuses, and event requirements so that generic procedural deck rules can generate legal, themed decks automatically.
Pre-Packaged Developer Baseline: All categories and tags listed in this reference are already completed and pre-packaged. You do not need to run any extractions or tag any cards—the procedural deck generator and filter dropdowns can use these categories immediately upon opening the app.
Taxonomy Design Philosophy — Structural Hooks vs. In-Game Modifiers:
The companion taxonomy dataset does not attempt to transcribe every situational penalty, dice modifier, or flavor handicap printed on card faces. (Cards already display those rules when in hand or on the table).

Instead, tags serve strictly as structural deck-building bridges between disparate card types:
  • Positive Strategic Enablers: Tags capture abilities that procedural rules actively search for—such as recruiting a faction (Faction Bonus), fighting a specific monster (Combat Bonus), or pairing a quest with its required enabler card (Prerequisite).
  • Why Negative Drawbacks are Omitted (e.g., Barliman Butterbur): Characters with situational handicaps (such as Barliman's "-1 to influence checks against factions") are never drafted for their penalties. They are drafted for their baseline stats (e.g. Mind: 1, Skill: Warrior, Home: Bree). Tagging negative modifiers would clutter the taxonomy with dead values that no procedural deck rule would ever query.
  • Avoiding Stat Duplication: Ratings already tracked in the official database (such as base Direct, Prowess, Mind, or official Corruption burden) are not duplicated as custom tags. Deck rules query those printed properties directly.
Card Examples & Set Conventions: Wherever possible, card examples throughout this guide are drawn from the base premiere set, The Wizards (METW). For gameplay mechanics introduced in subsequent expansions (such as Under-deeps sites introduced in The Dragons or minion/fallen mechanics from The Lidless Eye and The Balrog), the expansion set code is explicitly noted in parentheses (e.g. MEBA).

Where to Store Your Own Custom Tags

If you create your own taxonomy categories or tags using the Tag Manager or Extraction Tools, you have two choices for where to store them:

  • Option 1: Merge into the Auto-Loaded Baseline (Rules_Support_Tags.json): If you want your custom categories to load automatically every time you launch the application, choose Taxonomy > Save Tag Set..., select Rules_Support_Tags.json, and confirm overwrite.
  • Option 2: Save to a Modular Tag File (e.g. Tournament_Hazards.json): If you are creating specialized strategies or sharing tag sets with other players, save them to a standalone .json file. These files will not load automatically on launch; you pull them into your active session on demand via Taxonomy > Load Tag Set... or Taxonomy > Merge Tag Set....

2. Detailed Category Reference

Adjacent Sites

Card Scope: Site (Under-deeps sites only; surface sites remain [Blank])

Records all sites directly accessible from an Under-deeps site—including both surface site entrances and contiguous Under-deeps sites—with passage movement difficulty ratings stripped so they can be matched cleanly as card titles. This enables dynamic Under-deeps movement and expedition rules without hardcoding site pairs.

Representative Example:
  • Blue Mountain Dwarf-hold; Remains of Thangorodrim; The Under-vaults → Connected surface and Under-deeps sites for The Drowning-deeps (MEBA)

Automatic Attack

Card Scope: Site

Indexes guardian creature species printed on site cards using singular terms (e.g. Orc, not Orcs) to align directly with hazard creature race attributes. For sites that allow open attacks (e.g. "opponent may play any creature keyed to Ruins & Lairs" ), site predicates (e.g. Site=Ruins & Lairs) define which hazard creatures can attack there.

Sites vs. Events/Hazards: Automatic Attack is reserved strictly for site cards to record their native guardians. For resource or hazard events that create, modify, or cancel automatic attacks (such as Siege or Balrog of Moria), use Role: Automatic-attack.
Representative Examples:
  • Dragon → Dancing Spire, The Lonely Mountain
  • Orc; Troll → Barad-dûr, Dol Guldur
  • Spider → Ruined Signal Tower
  • Site=Ruins & Lairs; Site=Shadow-hold → Framsburg (METD — dynamic hold predicate)

Combat Bonus

Card Scope: Character

Flags characters providing combat advantages—such as direct prowess bonuses, body/survival bonuses, opponent body reduction, or strike roll modifiers—specifically against targeted creature species.

Characters vs. Non-Characters: Combat Bonus is reserved strictly for characters. For items, weapons, events, or hazards that modify combat or target specific creature types, use Role: Combat (the mechanism) and Target Species (the targeted species).
Representative Examples:
  • Orc → Character prowess/check bonuses on Dáin II and Gimli
  • Nazgûl → Character combat bonuses on Galva and Peath

Environment Stance

Card Scope: Resource • Hazard (Events & Creatures)

Tracks whether a card requires or benefits from Gates of Morning (Light) or Doors of Night (Shadow) being in play. (Items and allies do not use this tag, as environmental conditions only affect events and certain nocturnal creatures.) This supports two primary workflows:

  • Dedicated Strategy (Top-Down): When building a dedicated Gates of Morning or Doors of Night deck, filtering by this category quickly gathers all matching resource events, hazard events, and creatures that support that strategy.
  • Automated Prerequisite Support (Bottom-Up): When procedural deck rules draft cards that depend on day or night, the generator can automatically include Gates of Morning or Doors of Night in the deck so those cards can actually be played.
Stance Values:
  • Gates of Morning → Light-dependent cards (Clear Skies, Sun)
  • Doors of Night → Shadow-dependent cards (Foul Fumes, Shelob, The Will of Sauron)
  • Gates of Morning; Doors of Night → Dual-environment cards (Moon)

Faction Bonus

Card Scope: Character

Tracks character Direct Influence (DI) bonuses for recruiting specific named factions or entire species of factions. In procedural deck generation, querying "Name": "{Leader.Category:Faction Bonus}" automatically drafts the exact faction your company leader specializes in recruiting.

Faction Recruitment vs. Follower Influence (e.g., Balin, Dáin II):
Several diplomats feature printed text granting direct influence bonuses against both a faction and individual characters of that species (for example, Balin reads "+1 direct influence against Dwarves and Dwarf factions").
  • Why Factions are Tagged: Factions are external resource cards that must be deliberately included in your play deck. Faction Bonus provides the machine-actionable hook needed by procedural rules (e.g. "Name": "{Leader.Category:Faction Bonus}") to pull that faction into the deck.
  • Why Follower Influence is Omitted: Controlling followers in a company is governed by a character's printed Direct attribute and biological Race. Procedural company recruitment rules already draft companions by race (e.g. "Race": "{Leader.Race}") or DI capacity (e.g. "Direct": ">= 2"). Tagging Balin with follower influence would duplicate existing official attributes without adding functional deck-construction value.
Representative Examples:
  • Wood-elves → Specific named faction recruited with bonus by Thranduil
  • Iron Hill Dwarves; Man → Named faction and species recruitment bonuses on Dáin II
  • Riders of Rohan → Specific named faction recruited with bonus by Théoden
  • Dunlendings → Specific named faction recruited with bonus by Peath
  • All → Universal diplomat wildcard matching any faction in active expansions (Adrazar)

Home Region

Card Scope: Character

Connects each character's printed home site directly to its geographic territory. In procedural deck generation, querying "Home Region": "{Leader.Category:Home Region}" lets you recruit starting companions from your leader's home territory for natural regional cohesion.

Representative Examples:
  • Arthedain → Derived from Bree (Aragorn II)
  • Rhudaur → Derived from Rivendell (Elrond)
  • Anórien → Derived from Minas Tirith (Boromir II)
  • Rohan → Derived from Edoras (Théoden)

Prerequisite

Card Scope: Resource (Quests & Multi-Card Storylines)

Identifies the exact, named partner card(s) that an objective or quest card requires in company or discard to be played or scored. Used by procedural deck templates to automatically summon enabler events and relics without hardcoded titles.

Representative Examples:
  • Paths of the Dead → Enabler required on Army of the Dead
  • Narsil; Reforging → Relic and event required on Andúril, the Flame of the West
  • Men of Lamedon → Faction required on Stone of Erech

Prerequisite For

Card Scope: Resource (Enabler Events & Quest Relics)

The inverse companion to Prerequisite. Identifies which quest or storyline card this card enables.

The Enabler Shield Pattern: When drafting generic utility cards, querying "Prerequisite For": "[Blank]" guarantees that niche enablers (like Paths of the Dead) are never drafted as dead cards into decks that lack their parent quest.
Representative Examples:
  • Army of the Dead → Assigned to Paths of the Dead
  • Andúril, the Flame of the West → Assigned to Narsil and Reforging

Region Requirement

Card Scope: Hazard • Resource

Consolidates all card-to-region playability constraints and modifications into a single queryable category. Identifies:

  1. Geographic territories required to bring a card into play (e.g. hazard creatures keyed to specific regions), and
  2. Territories an ongoing event explicitly buffs, alters, or affects (e.g. regional combat modifiers or movement path adjustments).
Dual-Mode Cards (Creature / Event): For cards with dual card types (such as the Nazgûl), only tag the specific regions required to play them as a creature. Do not tag All to represent their event mode being globally playable—doing so would allow the deck generator to falsely draft the card as a creature in illegal regions (such as the Shire).
Representative Examples:
  • Harondor; Horse Plains; Gorgoroth; Khand → Playable creature territories for Akhôrahil
  • Imlad Morgul; Gorgoroth → Playable creature territories for Shelob
  • Dagorlad; Udûn → Movement path territories modified by Morannon (Event)
  • Hollin; Redhorn Gate; Wold & Foothills → Regional attacks buffed by Balrog of Moria (Permanent-event)

Region Type

Card Scope: Region • Site

Classifies the terrain classification printed on region movement cards. In the pre-packaged baseline taxonomy, these terrain types have already been propagated down to all site cards, enabling dynamic terrain queries on sites and movement paths (e.g. Region Type=Wilderness or Region Type=Shadow-land).

Canonical Terrain Classifications:
  • Free-domain → The Shire, Lindon, Anórien, Belfalas
  • Border-land → Anduin Vales, Rohan, Dorwinion, Woodland Realm
  • Wilderness → Arthedain, Cardolan, Rhudaur, Ithilien, Hollin
  • Shadow-land → Dagorlad, Brown Lands, Imlad Morgul, Angmar
  • Dark-domain → Gorgoroth, Udûn, Nurn, Southern Mirkwood
  • Coastal Sea → Bay of Belfalas, Mouths of the Anduin, Andrast Coast

Role

Card Scope: Resource • Hazard

Classifies the primary tactical game mechanism executed by non-character cards (events, items, hazards, allies). Symmetrical across alignments—the card's Primary type dictates whether the effect aids your company or disrupts the opponent.

Custom Roles: The 14 roles listed below represent the pre-packaged baseline taxonomy shipped in Rules_Support_Tags.json. You can define additional custom roles (such as Scout Support or Nazgûl Hunter) via Taxonomy > Manage Custom Tags... at any time.
Baseline Roles (Pre-packaged Dataset):
  • Automatic Attack — Modifies, buffs, cancels, or creates site guardian attacks faced by the whole company (Balrog of Moria, Siege). Note: Cards or allies with personal immunity to automatic-attack strikes (such as Treebeard or Goldberry) are classified under Role: Protection.
  • Card Flow — Managing cards between your hand, deck, and discard pile—drawing extra cards (Favor of the Valar), scouting or filtering your play deck (Far-sight, Mirror of Galadriel), retrieving cards from your discard pile (Mouth of Sauron), increasing hand size (Smoke Rings), or forcing an opponent to discard cards (Khamûl the Easterling).
  • Combat — Engaging in physical combat—boosting prowess or body during an attack, adjusting combat dice rolls, adding strikes, or triggering bonus attacks:
    • Company Martial Strength (Resources): Prowess buffs and combat tricks used by characters when fighting strikes (Block, Dodge, Risky Blow, Lucky Strike, Glamdring).
    • Attack Escalation & Lethality (Hazards): Buffing creature prowess, increasing strike counts, or triggering extra attacks against companies (Wake of War, Minions Stir, Orc-guard, Traitor, The Pale Sword).
  • Corruption — Strategic corruption offense or defense—forces corruption checks or burdens (Lure of Power, Despair of the Heart) or mitigates and heals corruption (Praise to Elbereth)
  • Duration — Extends the life or duration of active events in play (The Will of Sauron)
  • Influence — Modifies mathematical influence totals, control ratings, or influence check rolls:
    • Stat & Capacity Adjustments: Direct Influence (DI) ratings, general influence pools, or character control limits (Return of the King).
    • Influence Check Modifiers: Numerical bonuses or penalties to influence dice rolls made against characters, followers, or factions (Lordly Presence, Old Friendship, A Friend or Three, Persuasive Words).
    • Influence Attack / Opponent Stealing: Aiding or protecting against influence attempts made by opponent companies or agents.
  • Item — Retrieves, searches, transfers, protects, or forces the discard/theft of items (Lucky Search, Reforging, Align Palantír, Indûr Dawndeath).
  • Movement — Modifies travel, region pathing, or forces company return (Morannon)
  • Protection — Avoiding, mitigating, or surviving combat—cancelling attacks, dodging strikes, granting personal strike immunity, preventing wounds, or healing damage:
    • Attack & Strike Evasion: Cancelling attacks before strikes are rolled, or slipping away unseen (Concealment, Dark Quarrels, Escape, Halfling Stealth, Vanishment).
    • Immunity & Target Denial: Allies or characters that cannot be attacked or chosen as strike targets (Treebeard, Goldberry, Leaflock, Tom Bombadil).
    • Survival & Healing: Preventing wounds, shielding characters from discard when defeated, or healing damage after combat (Halfling Strength, Sacrifice of Form, Healing Herbs).
  • Quest — Directly advances victory conditions or scenario goals by awarding Marshalling Points (MPs) for completing specific site journeys or tasks (Andúril, Rescue Prisoners, Stone of Erech). Non-scoring utility cards that transform the board (such as The White Tree) are classified under their functional mechanism (e.g. Role: Site).
  • Readiness — Character and ally stamina and status—tapping, untapping, wounding, healing, or returning characters to hand (Adûnaphel, Call of Home). Note: Discarding or stealing items belongs under Role: Item, while altering or closing sites belongs under Role: Site.
  • Recruitment — Enables, accelerates, or alters the physical entry of characters and factions into play (beyond numerical check modifiers):
    • Location & Site Bypasses: Playing characters or factions at non-standard sites or alternative havens (A Chance Meeting).
    • Alternative Recruitment Engines: Enlisting factions through special substitute rules rather than standard diplomat influence checks (Muster, Roäc the Raven, The Great Eagles).
    • Recruitment Pacing: Playing extra characters in a turn or tutoring characters/factions directly from deck or discard.
    Influence vs. Recruitment (The "Muster" Edge Case):
    • Pure Influence: Cards that merely grant a numerical bonus to standard diplomat rolls (e.g. +5 on Lordly Presence or A Friend or Three) belong strictly under Role: Influence.
    • Pure Recruitment: Cards that alter sites, timing, or summon entities into play without a standard influence check (e.g. A Chance Meeting, Roäc the Raven) belong under Role: Recruitment.
    • Hybrid Cards (Muster): Under errata, Muster uses a warrior's prowess to modify an influence check. Because it both enables a martial class to recruit factions and modifies the check total, it carries dual tags: Role: Influence; Recruitment.
  • Site — Alters site status, hold types, or site playability (Witch-king of Angmar, The White Tree)
  • Terrain — Converts region path symbols and territory terrain classifications between hostile and safe (Fog, Morgul Night, Moon)

Site Requirement

Card Scope: Resource • Hazard

Consolidates all card-to-site relationships into a single queryable category. Identifies:

  1. The specific site(s) or hold type(s) where a company must be located to play the card (items, allies, factions, and site-phase events), and
  2. The specific site(s) or hold type(s) an event attaches to, targets, or modifies.

Supports specific named sites (e.g. Minas Tirith, Moria), structural site hold classifications (e.g. Dark-hold, Shadow-hold, Ruins & Lairs, Free-hold, Border-hold, Haven), and regional site filters (e.g. Region=Dagorlad).

Modal "OR" Events vs. Hard Prerequisites:
Only tag Site Requirement if the site or hold type is a mandatory prerequisite required to play the card (e.g. Rescue Prisoners requiring a Dark-hold or Shadow-hold, or Siege requiring a Border-hold or Free-hold).

If an event features an unconstrained primary mode alongside an optional keying branch (such as Dragon's Desolation, which offers "+2 prowess to any Dragon attack OR play a Dragon at Ruins & Lairs"), leave Site Requirement [Blank]. Tagging the conditional enabler would falsely brand the card as a site-locked hazard in procedural rules, preventing general decks from drafting it as open combat support.
Representative Examples:
  • Dark-hold; Shadow-hold → Permitted play sites for Rescue Prisoners
  • Bag End; Bree → Required play sites for Bill the Pony
  • Minas Tirith → Target attachment site for The White Tree
  • Border-hold; Free-hold → Target sites for Siege
  • Ruins & Lairs → Target sites for Awaken Denizens
  • Moria; Lórien → Target sites for Balrog of Moria
  • Region=Dagorlad → Geographic site restriction for Morannon

Target Item

Card Scope: Resource • Hazard

Identifies specific item classifications, gear keywords, or magical objects that a resource or hazard event requires in company, enhances, transfers, tests, or targets for corruption/theft.

Representative Examples:
  • Palantír → Required in company for Align Palantír and Bane of the Ithil-stone
  • Weapon; Armor → Target item types for Reforging
  • Gold Ring → Required item type for Test of Form and The Precious
  • Lost Knowledge → Required tome/scroll type for Into the Smoking Cone

Target Species

Card Scope: Resource (Weapons, Items, Allies, Events) • Hazard

Identifies specific biological species or creature races (e.g. Elf, Dúnadan, Wizard, Nazgûl, Orc) that an event, weapon, item, ally, or hazard explicitly targets, modifies, or aids. Supports exact species names as well as dynamic exclusion predicates.

Named Characters vs. Species: Do not use this category for specific named individuals (such as Aragorn II). Named character requirements are official database properties tracked directly under the Specific attribute (e.g. Specific: Aragorn II on Return of the King).
Representative Examples:
  • Orc → Weapons targeting Orcs (Glamdring, Orcrist) or allies aiding against Orcs (Beorn)
  • Nazgûl → Weapons or attacks targeting Nazgûl (Dagger of Westernesse, The Pale Sword)
  • Wizard → Targets or requires a Wizard (Sacrifice of Form)
  • Dúnadan → Grants prowess bonuses to Dúnedain (Andúril, the Flame of the West)
  • Hobbit → Grants body protection to Hobbits (Halfling Strength)
  • Race!=Hobbit && Race!=Wizard → Excludes Hobbits and Wizards from corruption check (Despair of the Heart)

3. Using Companion Categories in Procedural Deck Rules

These companion categories enable rich, declarative deck generation rules:

A. Universal Starting Site Rule (Handling Standard & Dynamic Characters)

Because dynamic home rules are modeled directly as predicates in the official Home attribute (e.g. Site=Haven, Site=Dark-hold, Region=Under-deeps && Site!=Dark-hold), a single rule recruits legal starting sites for 100% of characters with zero boilerplate: 

{
  "Name": "Leader's Starting Site",
  "Section": "Sites",
  "Count": 1,
  "Attributes": {
    "Primary": "Site",
    "Name": "{Leader.Home}"
  }
}
Execution Walkthrough:
  • Standard Characters (Aragorn, Boromir, Frodo): {Leader.Home} resolves to a specific site title (e.g. "Rivendell"). The rule finds the site and succeeds.
  • Dynamic Characters (Gandalf, Doeth, Crook-legged Orc): {Leader.Home} resolves to the predicate (e.g. Site=Haven, Site=Dark-hold, or Region=Under-deeps && Site!=Dark-hold). The engine evaluates the predicate on the fly and draws randomly from all matching sites in your active expansions!

B. Automated Destination Sites for Quest Events (Site Requirement)

When your deck includes site-specific quest events (such as Rescue Prisoners or The White Tree), capture the event into a variable and draft destination sites dynamically using Site Requirement: 

[
  {
    "Name": "Rescue Prisoners Quest",
    "SaveAs": "RescueQuest",
    "Section": "Resources",
    "Count": 1,
    "Attributes": {
      "Name": "Rescue Prisoners"
    }
  },
  {
    "Name": "Rescue Destination Sites",
    "Section": "Sites",
    "Count": 2,
    "Attributes": {
      "Primary": "Site",
      "Name": "{RescueQuest.Category:Site Requirement}"
    }
  }
]

C. Targeted Dragon Lair Expedition

Recruit destination sites specifically guarded by true Dragons without hardcoding site names: 

{
  "Name": "Dragon Lair Destinations",
  "Section": "Sites",
  "Count": 2,
  "Attributes": {
    "Primary": "Site"
  },
  "Categories": {
    "Automatic Attack": "Dragon"
  }
}

D. Regional Themed Recruitment

Recruit backup characters whose home site is located in the same geographic region as the company leader: 

{
  "Name": "Regional Reinforcements",
  "Section": "Pool",
  "Count": 2,
  "Attributes": {
    "Primary": "Character"
  },
  "Categories": {
    "Home Region": "{Leader.Category:Home Region}"
  }
}

E. Drafting Regional Hazards (Region Requirement)

Draft hazard creatures keyed strictly to a specific geographic region using Region Requirement: 

{
  "Name": "Gorgoroth Guardians",
  "Section": "Hazards",
  "Count": 3,
  "Attributes": {
    "Secondary": "Creature"
  },
  "Categories": {
    "Region Requirement": "Gorgoroth"
  }
}
