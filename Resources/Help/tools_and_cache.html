Tools & Image Cache Architecture

Card Artwork Cache System

The application employs a two-tier caching architecture:

  1. Memory Cache: An in-memory cache holding up to 10,000 active Bitmaps for instant display when scrolling or clicking.
  2. Local Disk Cache: Whenever a card image is requested, the application checks for an existing image on disk under a folder matching the set code (e.g., METW/metw_adrazar.jpg).
    • If found locally, the image loads immediately with zero network latency.
    • If not found, it downloads from Cardnum, saves a copy into the set folder, and stores it in memory.

Batch Image Downloader

If you plan to use MECCG Deck Builder offline (e.g., on a laptop during tournaments or travel), you can pre-download card images:

  1. Enable all sets you want cached via the Set menu.
  2. Reset your filters so that all cards are listed in the Master List.
  3. Select Tools > Download Images.
Note: The batch downloader runs asynchronously in the background with real-time progress reported in the window title bar, ensuring the application remains responsive while saving each card image to disk.

Offline Data Fallbacks

The builder is resilient against network outages:

  • Cards: Automatically attempts to download the latest card definitions from Cardnum on launch. If offline or unavailable, it seamlessly falls back to the bundled local cards-dc.json file.
  • Sets: Automatically attempts to download the latest expansion set metadata. If offline, it reads the bundled local sets-dc.json file.

Procedural Deck Generation (Tools > Generate Deck from Rules... / F5)

MECCG Deck Builder features an automated generation engine that builds legal, randomized decks from declarative JSON rule templates.

  • Symmetric Filtering: Rules can query official card attributes (Primary, Race, Skill) and custom taxonomy tags (Faction Focus, Home Region).
  • Multi-Value "OR" Syntax: Semicolon-delimited values (e.g. "Secondary": "Major Item; Minor Item") match cards satisfying any of the listed options.
  • Copy Limits & Uniqueness: Strictly enforces game legality: maximum 1 copy for unique cards and maximum 3 copies for non-unique cards across the entire deck.
  • Tiered Variety-First Distribution: To maximize card variety, the engine exhausts all 0-copy (unused) cards before assigning 2nd copies, and all 2-copy cards before assigning 3rd copies.
  • Branching Choice Groups (RandomChoice): Author multiple deck archetypes (e.g., Dwarf Company vs. Elf Company, or Nazgûl vs. Dragon hazards) in a single rule file with weighted random selection and dynamic title overrides.
  • Instant Re-run (F5): Press F5 to re-run the last used rules file directly from disk without re-opening file dialogs.

Relational Attribute Lookup (Cross-Card Join)

Located under Tools > Extract Taxonomy with Rules..., this mode enables 2-step relational tagging between linked entities:

  • Source Field: Reads an attribute from cards in scope (e.g. Character Home).
  • Lookup Entity: Matches corresponding cards in the catalog (e.g. Primary = Site).
  • Extract Field: Reads the destination attribute (e.g. Site Region) and writes it into a custom category (e.g. Home Region).
  • Compound Token Parsing: Characters with multiple homesites (e.g. Rivendell, Bree) automatically resolve both sites to generate semicolon-delimited multi-tags (Arthedain; Rhudaur).
