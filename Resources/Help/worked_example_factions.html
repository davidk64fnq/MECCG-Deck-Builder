Worked Example: Dynamic Faction Recruitment

This end-to-end tutorial demonstrates how several advanced features of MECCG Deck Builder work together to solve a complex deck construction problem:

1. The Goal: Context-Aware Deck Archetypes

In MECCG, leaders often possess direct influence (DI) bonuses against specific factions (for example, Thranduil receives +2 DI against the Wood-elves, and Dáin II receives +2 DI against the Iron Hill Dwarves).

We want to create an automated deck generator rule set that:

  1. Randomly selects a company archetype (e.g. Dwarf Company vs. Elf Company).
  2. Selects an appropriate starting diplomat leader for that company and captures them in memory.
  3. Dynamically recruits the specific faction our leader specializes in influencing.
  4. Gracefully falls back: If the randomly chosen leader has no faction influence bonus, the generator must automatically fall back to recruiting any faction matching that leader's race.

2. Step 1: Scoping the Master List & Auto-Tagging Faction Bonuses

The extraction engine operates strictly on the cards currently visible in the Master List. The cards in this list are determined by two factors:

  • Active Expansions: Checked sets in the top Set menu.
  • Active Filters: The four filter slot pairs at the bottom of the window.

Since we only want to evaluate and tag characters for direct influence bonuses, we narrow the Master List before opening the tool:

A. Scope the Master List to Characters

  1. Click Set in the top menu and ensure your desired expansions are checked (e.g. The Wizards, The Dragons, Dark Minions).
  2. In Filter Slot 1 (bottom left):
    • Set the top dropdown (Attribute) to Primary.
    • Set the bottom dropdown (Value) to Character.
  3. Leave Slots 2, 3, and 4 blank (or press Ctrl+R before setting Slot 1). The Master List now displays only characters from your selected sets.

B. Run the Dynamic Entity Harvest

  1. Open Tools > Extract Taxonomy with Rules....
  2. Note the dialog title and scope hint banner confirming: "Scanning [X] card(s) currently visible in the Master List."
  3. Select the Dynamic Entity Harvest (from Catalog Text) radio button.
  4. Configure the extraction fields:
    • Target Category: Enter Faction Bonus.
    • Attribute: Select Secondary.
    • Value: Select Faction.
  5. Click Test / Preview Matches. The engine performs a two-step query:
    • It scans all active catalog sets in memory to harvest published faction titles (e.g. Wood-elves, Iron Hill Dwarves, Riders of Rohan).
    • It strips all Tolkien flavor quotes from your scoped characters' rules text and flags every character whose active gameplay rules reference one of those factions (e.g. "+2 direct influence against Wood-elves").
  6. Click Apply Tags to Catalog. Your characters are now permanently assigned structured tags in your session taxonomy (e.g. Thranduil → Faction Bonus: Wood-elves, Dáin II → Faction Bonus: Iron Hill Dwarves).
Faceted Filter Verification: Once applied, you can immediately test these tags in the main window: reset Slot 1, select Category = Faction Bonus in Slot 3, and watch the Tag dropdown populate with all harvested factions!

3. Key Generation Concepts Explained

A. Archetype Branching (RandomChoice)

The RandomChoice rule type rolls weighted random branches at runtime. Each branch can define its own unique sub-rules and automatically update the deck title (e.g., "Hero Elves of the Woodland Realm").

B. Runtime Variable Capture (SaveAs)

Adding "SaveAs": "Leader" to a rule captures whichever character is randomly sampled into a temporary execution context. Subsequent rules can reference that card's properties using {Leader.Attribute} or {Leader.Tag:Category}.

C. Direct Card Title Access (Name)

In the application interface, the filter dropdowns and context menus list official game rules statistics (such as Race, Skill, Mind, Direct). However, inside the rules engine, Name is a fully queryable attribute. Querying "Name": "{Leader.Tag:Faction Bonus}" matches the faction card whose title equals the leader's tagged bonus.

D. Token Interpolation & Multi-Value OR Matching

If a character possesses bonuses for multiple factions (e.g. Wood-elves; Silvan Elves), the token resolves to a semicolon-delimited string. The engine automatically evaluates this as an OR query, matching either faction.

E. Automated Shortfall Fallbacks (Fallback)

If the leader has no faction bonus tag, or if that faction is unique and already at its deck limit, the primary rule experiences a shortfall (0 of 1 added). Instead of halting or leaving an incomplete deck, the engine detects the shortfall and immediately executes the nested Fallback rule for the remaining count.

5. Step 3: Running and Verifying the Deck

  1. Click Tools > Generate Deck from Rules... and pick Hero_Faction_Rules.json.
  2. Inspect the generation summary dialog:
    • Scenario A (Leader has Tag): If the generator selects Dáin II, the primary rule resolves Name: Iron Hill Dwarves and adds it directly to Resources.
    • Scenario B (Leader has no Tag): If the generator selects a leader with no bonus tag (such as Balin), the primary rule resolves to blank, adds 0 cards, and immediately hands off to the Fallback rule. The fallback resolves Race: Dwarf and recruits a generic dwarf faction (such as Blue Mountain Dwarves).
  3. Press F5 (Tools > Re-run Deck Rules) to generate instant variations with new leader, faction, item, and hazard combinations.
