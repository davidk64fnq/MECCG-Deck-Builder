Taxonomy Extraction Tools

Located under Taxonomy > Extract Tags with Rules..., this dialog provides automated classification tools scoped strictly to the cards currently visible in your Master List. It allows you to scan card text, cross-reference related cards, or execute text pattern rules to tag hundreds of cards in bulk.

Pre-Packaged Baseline Notice: The extraction workflows demonstrated below (such as tagging Dark-holds, scanning faction recruiting bonuses, and mapping home regions) represent the exact automated methods used to build Rules_Support_Tags.json. Because these tags are already shipped with the software, you do not need to run these extractions yourself before building decks—they are documented here so you can inspect the methodology and apply it to your own custom classifications.
Master List Scoping: All extraction tools evaluate only the cards currently visible in the Master List. To target specific cards (e.g. only characters or only cards from a specific expansion), set your filters in the main window before opening the dialog.

Scan Card Text for Catalog Entities

Scans the gameplay rules text of cards in scope for references to published catalog cards (such as factions, regions, or character names):

  • Target Entity: Select the official attribute and value that defines the catalog cards you want to search for (e.g. Secondary = Faction or Primary = Region). The engine inspects all active sets and gathers all published titles (e.g. Wood-elves, Riders of Rohan).
  • Save to Category: Enter the custom category where matching tags will be stored (e.g. Faction Bonus).
  • Flavor Text Protection: All Tolkien book quotes (enclosed in quotation marks) and book citations (e.g. —LotRI) are automatically stripped before evaluation, ensuring lore quotes never generate false tags.

Worked Example: Extracting Faction Recruiting Bonuses

Many characters have rules text conferring Direct Influence bonuses when recruiting specific factions (e.g. Thranduil → Wood-elves, Dáin II → Iron Hill Dwarves). We can scan the text of all characters across the catalog and tag them with their recruitable factions automatically:

  1. Scope the Master List: In the main window, check your active expansions in the Catalog menu. In Filter Slot 1, set Attribute: Primary and Value: Character so only character cards are evaluated.
  2. Configure the Scanner: Open Taxonomy > Extract Tags with Rules..., choose Scan Card Text for Catalog Entities, and enter:
    • Target Entity: Secondary = Faction
    • Save to Category: Faction Bonus
  3. Preview and Apply: Click Test / Preview Matches to inspect all characters whose gameplay text references a published faction title. Click Apply Tags to Catalog, then persist your tags via Taxonomy > Save Tag Set... overwriting Rules_Support_Tags.json.

Cross-Card Property Lookup (Attributes & Categories)

Cross-references an official attribute or custom category on cards in scope (such as a character's Home or a site's Region) against related destination cards across the catalog (such as a Site or Region card) to pull in a secondary attribute or category (such as Region or Region Type) as a custom tag:

  • Read Property: The official attribute or custom category on cards in scope used to match the destination entity (e.g. Site Region).
  • Lookup Entity: The catalog criteria identifying the destination cards (e.g. Primary = Region). Supports matching both official properties and custom categories.
  • Extract Property: The official attribute or custom category pulled from matched cards (e.g. custom category Region Type).
  • Save to Category: The custom category where the extracted tag will be saved.

Worked Example: Propagating Region Terrain Types to Sites

While region cards carry terrain classifications (Wilderness, Shadow-land, etc.), site cards only list geographic region names (e.g. Rohan). Once your region cards have custom tags under Region Type, you can propagate those terrain types down to all site cards automatically:

  1. Scope the Master List: In the main window, set Filter Slot 1: Attribute: Primary, Value: Site so only site cards are in scope.
  2. Configure the Lookup: Open Taxonomy > Extract Tags with Rules..., choose Cross-Card Attribute Lookup, and enter:
    • Read Attribute: Region *(on the site card)*
    • Lookup Entity: Primary = Region *(matches region cards)*
    • Extract Attribute: Region Type *(extracts the custom category from region cards)*
    • Save to Category: Region Type
  3. Preview and Apply: Click Test / Preview Matches, then click Apply Tags to Catalog. Every site card across your expansions is now tagged with its terrain type, enabling dynamic queries like Region Type=Wilderness!

Worked Example: Mapping Character Homes to Geographic Regions

Character cards list home sites (e.g. Aragorn II → Rivendell, Boromir → Minas Tirith, Théoden → Edoras), but lack geographic region attributes. To enable regional company recruitment rules without manual tagging:

  1. Scope the Master List: In the main window, check your active expansions in the Catalog menu, and set Filter Slot 1: Attribute: Primary, Value: Character.
  2. Configure the Lookup: Open Taxonomy > Extract Tags with Rules..., choose Cross-Card Attribute Lookup, and enter:
    • Read Attribute: Home
    • Lookup Entity: Primary = Site
    • Extract Attribute: Region
    • Save to Category: Home Region
  3. Preview and Apply: Click Test / Preview Matches. The engine looks up each character's home site and extracts its region (e.g. Rivendell → Rhudaur, Minas Tirith → Anórien, Edoras → Rohan). Click Apply Tags to Catalog and save via Taxonomy > Save Tag Set....

Custom Pattern Search (Regex)

Searches card rules text using custom .NET regular expressions:

  • Pattern: The text pattern evaluated against card rules text (e.g. Ruins & Lairs in a Wilderness or \b(greater)\b). Case-insensitivity is enabled by default.
  • Assigned Tag: The tag applied to matching cards. Supports three formats:
    • Fixed Text: A single fixed tag (e.g. Cancellation).
    • Multi-Tag List: A semicolon-delimited string (e.g. Barad-dûr; Carn Dûm; Cirith Gorgor).
    • Capture Group ($1): If your pattern contains parentheses (...), using $1 dynamically assigns the exact captured word or phrase.
  • Save to Category: The custom taxonomy category where assigned tags will be stored.
Session Persistence: Your last-used Pattern, Assigned Tag, and Category are automatically remembered across application launches so you can make iterative passes without retyping.

Worked Example: Batch-Tagging Minion Dark-holds

In The Lidless Eye, 15 Minion Orcs, Trolls, and Half-orcs (such as Doeth, Orc Captain, and Troll Lout) have the non-specific home rule Home Site: Any Dark-hold. To allow procedural deck rules to recruit these characters and automatically assign them a valid starting site, we can batch-tag all 15 characters in under 30 seconds:

  1. Scope the Master List: In the main window, check The Lidless Eye (MELE) in the Catalog menu, and set Filter Slot 1: Attribute: Home, Value: Any Dark-hold.
  2. Configure the Pattern Search: Open Taxonomy > Extract Tags with Rules..., choose Custom Pattern Search (Regex), and enter:
    • Pattern: Any Dark-hold
    • Assigned Tag: Barad-dûr; Carn Dûm; Cirith Gorgor; Cirith Ungol; Dol Guldur; Minas Morgul; Urlurtsu Nurn
    • Save to Category: Resolved Site
  3. Preview and Apply: Click Test / Preview Matches to verify the 15 characters, then click Apply Tags to Catalog. Persist your changes via Taxonomy > Save Tag Set... overwriting Rules_Support_Tags.json.

Batch Rules from File (.json)

For large-scale taxonomy extraction across multiple expansions, you can author batch extraction rule files (.json) containing arrays of compiled regex rules and execute them in a single operation.

Batch Rule Schema

Property Type Description
Category string The custom taxonomy category where matches will be saved (e.g. "Automatic Attack").
Pattern string The .NET regular expression to evaluate against card rules text. Backslashes must be double-escaped for JSON encoding (e.g. "\\b", "\\s+").
TagTemplate string The tag assigned upon match. Can be a fixed string (e.g. "Dwarf") or a capture group token (e.g. "$1").

Worked Example: Sandboxed Site Automatic Attacks

The Goal: We want to classify all site cards across our expansions by the guardian creature species printed in their automatic attack (tagging them as Dragon, Orc, Troll, Undead, or Dwarf under the custom category Automatic Attack).

The Challenge: Site cards print automatic attacks in the middle of their rules box, between surface entrances at the top and special site rules at the bottom. A simple text search for creature names causes two distinct false matches:

  1. Top False Matches (Adjacent Sites / Havens): Under-deeps sites list surface entrances at the very top. For example, The Drowning-deeps begins with Adjacent Sites: Blue Mountain Dwarf-hold (13)..., triggering a false Dwarf tag even though its actual attack is a Drake.
  2. Bottom False Matches (Special Rules): Many sites list special racial bonuses or movement effects at the bottom. For example, a site guarded only by Orc might conclude with Special: Dwarven characters receive +1 direct influence here, triggering an unwanted Dwarf tag.
Building a Two-Sided Search Sandbox:

To isolate only the true automatic attack, we use a tempered regex pattern that starts at the attack header and stops before the special text:

(?is)Automatic-attacks?(?:(?!Special:).)*?\bdwar(?:f|ves)\b
  • (?is)Automatic-attacks?: The Top Guard. Anchors to the attack header, ignoring all site names in Adjacent Sites: or Nearest Haven: above it.
  • (?:(?!Special:).)*?: The Bottom Guard. Advances across lines character-by-character, strictly verifying that it has not reached Special:.
  • \bdwar(?:f|ves)\b: Matches the creature species. If Special: is encountered before the creature name, the match fails immediately.

1. Sample Sandboxed Rule File (Automatic_Attack_Rules.json)

[
  {
    "Category": "Automatic Attack",
    "Pattern": "(?is)Automatic-attacks?(?:(?!Special:).)*?\\bdwar(?:f|ves)\\b",
    "TagTemplate": "Dwarf"
  },
  {
    "Category": "Automatic Attack",
    "Pattern": "(?is)Automatic-attacks?(?:(?!Special:).)*?\\bdrakes?\\b",
    "TagTemplate": "Drake"
  },
  {
    "Category": "Automatic Attack",
    "Pattern": "(?is)Automatic-attacks?(?:(?!Special:).)*?\\borcs?\\b",
    "TagTemplate": "Orc"
  },
  {
    "Category": "Automatic Attack",
    "Pattern": "(?is)Automatic-attacks?(?:(?!Special:).)*?\\btrolls?\\b",
    "TagTemplate": "Troll"
  },
  {
    "Category": "Automatic Attack",
    "Pattern": "(?is)Automatic-attacks?(?:(?!Special:).)*?\\b(?:undead|wights?|ghosts?)\\b",
    "TagTemplate": "Undead"
  }
]

2. Step-by-Step Batch Execution & Audit Workflow

  1. Scope the Master List: In the top Catalog menu, check your target expansions (e.g. The Dragons, Dark Minions, The Lidless Eye). In Filter Slot 1, set Attribute: Primary and Value: Site so only site cards are evaluated.
  2. Load and Run the Batch File: Open Taxonomy > Extract Tags with Rules..., select Batch Rules from File (.json), browse to Automatic_Attack_Rules.json, and click Test / Preview Matches. Review the preview list, then click Apply Tags to Catalog.
  3. Audit via CSV Spreadsheet Pipeline: In the main window, set Slot 3: Category: Automatic Attack and select Taxonomy > Export Taxonomy Draft (CSV)....
  4. Review in Excel or Google Sheets: Open the CSV to glance down the pre-populated Automatic Attack column. Multi-attack sites (like Carn Dûm or Moria) cleanly show multiple tags (Orc; Troll), and complex edge cases can be edited directly in the spreadsheet.
  5. Sync and Persist: Save the CSV and choose Taxonomy > Import Taxonomy (CSV)... to apply your edits. Finally, select Taxonomy > Save Tag Set..., choose Rules_Support_Tags.json, and confirm overwrite so all tags persist permanently across application launches.
