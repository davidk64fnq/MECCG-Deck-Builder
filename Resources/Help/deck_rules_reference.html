Deck Rules JSON Schema Reference

Procedural deck generation templates are declarative JSON files loaded via Deck > Generate from Rules... (Ctrl+G, or re-run instantly with F5). This reference details all JSON schema elements, properties, data types, default values, distribution strategies, relational operators, and token interpolation rules.

1. Root Object (DeckGenerationRuleSet)

Property Type Default Description
DeckTitle string "Generated Deck" Default title assigned to the deck. Can be dynamically overridden by a branch choice at runtime.
RuleSetType string "SequentialRules" Execution strategy identifier.
Version string "1.0" Schema version indicator.
Rules array of objects [] An ordered list of DeckGenerationRule objects evaluated sequentially from top to bottom.

2. Rule Object (DeckGenerationRule)

Property Type Default Description
RuleType string "FilterQuery" Rule mode:
  • "FilterQuery": Standard query that samples matching cards.
  • "RandomChoice" (or "Choice" / "OneOf" / "Or"): Evaluates a weighted random branch from Choices.
Name string "" Descriptive name displayed in generation logs and shortfall notices.
Section string "Resources" Target deck partition: "Pool", "Resources", "Hazards", "Sideboard", or "Sites".
Count integer 1 The total number of card copies requested by this rule.
Distribution string "Variety" Card sampling strategy:
  • "Variety" (default): Prioritizes distinct card titles (variety-first) before assigning duplicate copies.
  • "Focused" (or "Playset"): Concentrates additions into full legal playsets (up to 3 copies for non-unique cards, 1 for unique) of each sampled title before picking a different card.
  • "Uniform" (or "Random"): Unweighted random draw with replacement from all candidates that have not yet reached copy limits.
SaveAs string "" Captures all cards successfully selected by this rule into an in-memory variable (e.g. "Leader" or "ExpeditionSites"). If Count is greater than 1, downstream placeholders ({VariableName.Property}) resolve to a deduplicated, semicolon-delimited union set across all captured cards.
Sets array of strings [] Restricts sampling to specific expansion set codes (e.g. ["METW", "MEDM"]). If omitted, defaults to the sets currently checked in the app's Catalog menu.
Attributes dictionary (Attribute: Value) {} Key-value pairs of official card attributes and required values. Supports exact strings, semicolon OR logic, relational operators (>, >=, <, <=, !=), "[Blank]", and variable interpolation.
Categories dictionary (Category: Tag) {} Key-value pairs of custom taxonomy categories and required tags. Supports semicolon OR logic, "[Blank]", and variable interpolation.
Fallback object null A nested DeckGenerationRule executed automatically if this rule fails to fulfill its requested Count (due to missing tags, zero matching candidates, or deck uniqueness limits). Inherits the parent's target Section if unspecified.
Choices array of objects [] Used when RuleType is "RandomChoice". Contains weighted branches.

2.A Geographic Theater Rule Object (GeographicTheater)

Used when RuleType is "GeographicTheater" (or "Theater"). Constructs cohesive regional play areas using Middle-earth's Adjacent Regions graph layer, supporting pure Starter Movement hubs and contiguous roaming clusters with automatic starting haven and transit pathing:

Property Type Default Description
Mode string "Starter Only" Movement strategy:
  • "Starter Only": Pure Haven hub. Identifies candidate regions containing sites where Nearest Haven == Haven. Adds 0 region cards to the site deck.
  • "Starter + Region": Contiguous roaming cluster. Expands an adjacent cluster of contiguous regions from the haven's home territory and adds the <Region> cards to the Sites partition.
Haven string "Random" Anchor Haven: "Rivendell", "Lórien", "Grey Havens", "Edhellond", valid non-Hero havens (e.g. "Dol Guldur"), or "Random".
Smart Haven Snapping: If a non-haven site (such as Bree or Minas Tirith) is specified, the engine snaps to its printed nearest haven (Rivendell, Edhellond) for both modes. Unrecognized site names or typos fall back safely to Rivendell with a trace note.
RegionCount integer 4 Total number of contiguous regions in the theater. Defaults to 4 (guaranteeing that any local site-to-site move is reachable in a single turn). Higher values (e.g. 5 to 8) can be specified to create wider multi-turn campaign corridors.
RegionType string "" Optional Middle-earth terrain filter constraining the contiguous cluster and drafted adventure sites:
  • Terrain Inclusions: Semicolon-separated terrain types (e.g. "Wilderness; Border-land", "Coastal Sea; Free-domain").
  • Terrain Exclusions (!=): Excludes hostile terrain from the theater (e.g. "!=Dark-domain; !=Shadow-land").
SiteCount integer 0 Optional number of adventure sites to sample directly within the active theater. If omitted or 0, adventure sites can be drafted by downstream rules using "Region": "{Theater.Region}".
SiteType string "" Optional site hold classification filter constraining adventure sites drafted via SiteCount (or downstream rules):
  • Hold Inclusions: Semicolon-separated hold types (e.g. "Free-hold; Border-hold; Ruins & Lairs").
  • Hold Exclusions (!=): Excludes lethal holds from automatic drafting (e.g. "!=Dark-hold; !=Shadow-hold").
IncludeOverlandPath boolean false If true in Starter + Region mode, uses Breadth-First Search (BFS) on the Adjacent Regions graph to add the shortest contiguous region path from Rhudaur (Rivendell) to the theater.
IncludeIntermediateHavens boolean true If true, automatically adds intermediate stepping-stone havens for Haven-to-Haven starter movement (e.g. Lórien or Grey Havens when traveling to Edhellond).
SaveAs string "Theater" Captures the active theater into context variables, enabling downstream rules to query {Theater.Haven} and {Theater.Region}.

3. Branch Choice Object (DeckGenerationChoice)

Property Type Default Description
Name string "" Branch label recorded in the execution log (e.g. "Dwarf Company").
DeckTitle string "" Optional deck title override applied if this branch is selected.
Weight integer 1 Relative lottery weight. Selection probability equals Weight / Total Weights.
Rules array of objects [] The list of sub-rules executed sequentially if this branch wins the roll.

4. Query Syntax, Relational Operators & Placeholder Interpolation Rules

A. Numeric Relational Operators (>, >=, <, <=, !=)

For integer attributes (Prowess, Body, Mind, Direct, Corruption, MPs, Strikes), prefix numbers with relational operators:

  • "Prowess": ">= 6" — Characters with prowess 6 or higher.
  • "Mind": "<= 3" — Low-mind starting companions.
  • "Corruption": "< 0" — Corruption-resistant characters (Hobbits, Dwarves).
  • "MPs": "!= 0" — Cards worth non-zero victory points.
  • "Mind": ">= 3; <= 5" — Range query matching characters between 3 and 5 mind.
  • "Prowess": ">= 7; 1" — Tiered query matching warriors of prowess 7+ OR a 1-prowess scout.

B. Negative Exclusion & Inequality Matching (!=)

Prefix any attribute value or taxonomy tag with != to reject cards possessing that trait. Exclusions can be chained with semicolons:

  • "Site": "!=Dark-hold; !=Shadow-hold" — Rejects any site classified as a Dark-hold or Shadow-hold (evaluated as AND logic across all exclusions).
  • "Role": "!=Combat; !=Automatic Attack" — Excludes combat tricks from generic event or item draws.
  • "Race": "Dúnadan; Dwarf; !=Hobbit" — Combines positive inclusions (OR) with strict negative exclusions (AND).
  • "Adjacent Sites": "!=[Blank]" — Matches cards that have at least one tag assigned under Adjacent Sites.

C. Blank & Missing Value Matching ("[Blank]")

To query cards that have no value assigned for an attribute or category, use "[Blank]":

  • "Corruption": "[Blank]" — Corruption-free weapons and items.
  • "Home": "[Blank]" — Characters with open starting and healing options.
  • "Specific": "[Blank]" — Generic events and items that are not locked to a specific named character or site.
  • "Skill": "[Blank]" — Open events playable by any company without requiring specific classes (such as Sage, Ranger, or Scout).

D. Semicolon Multi-Value OR Logic

Any string inside Attributes or Categories can contain multiple semicolon-delimited values. A card matches if it satisfies any of the values: 

"Attributes": {
  "Skill": "Warrior; Scout",
  "Secondary": "Major Item; Minor Item"
},
"Categories": {
  "Automatic Attack": "Dragon; Drake"
}

E. Wildcard & Universal Sentinel Matching (* and All)

Any query criterion in Attributes or Categories that contains * or All acts as a wildcard, satisfying that check for any card that meets the other constraints in the rule. This is particularly valuable when querying properties dynamically captured from character cards: 

"Attributes": {
  "Primary": "Resource",
  "Secondary": "Faction",
  "Name": "{Leader.Category:Faction Bonus}"
}

If the captured leader is a universal diplomat like Adrazar (tagged Faction Bonus: All), the placeholder resolves to "Name": "All". Rather than failing to find a card literally named "All", the engine recognizes the sentinel, treats the Name criterion as an open wildcard, and randomly samples from all faction cards available in your active expansions.

G. Dynamic Attribute Predicate Selectors (Attribute=Value)

Custom taxonomy tags and procedural generation rules support dynamic rules predicates using the Attribute=Value syntax:

  • "Site=Haven" — Matches any Haven site card (e.g. Rivendell, Lórien, Grey Havens, Edhellond).
  • "Site=Dark-hold" — Matches any Dark-hold site card (e.g. Barad-dûr, Dol Guldur, Carn Dûm).
  • "Site=Ruins & Lairs" — Matches site cards or creature hazards keyed to Ruins & Lairs.
  • "Site=Shadow-hold" — Matches site cards or creature hazards keyed to Shadow-holds.
  • "Site=Free-hold" — Matches any Free-hold site card.
  • "Region=Udûn" — Matches site cards in the Udûn region (e.g. Cirith Gorgor) with automatic diacritic resilience (matching Udun, Udûn, or Ûdun).
  • "Alignment=Neutral" — Matches neutral faction, ally, or site cards.
  • "Corruption=[Blank]" — Matches cards with no corruption burden.
  • "Adjacent Sites!=[Blank]" — Matches cards that have at least one custom tag assigned under Adjacent Sites (useful for identifying Under-deeps entrances).
Canonical Site Names vs. Shorthand Symbols:
Always use full canonical site names (such as Site=Ruins & Lairs, Site=Shadow-hold, or Site=Haven) in deck rules and custom tags. Single-letter symbols (such as w or s) are disallowed in rule queries because ICE typography overloaded letters between site hold types and region terrain symbols (for example, w represented a Wilderness region symbol, whereas W represented a Wizardhaven site).

Composite Semicolon Lists & Compound AND Logic:
Predicates and standard card titles can be combined in semicolon lists (OR logic). You can also chain multiple predicates together within a single token using && (AND logic):

Example A — Semicolon OR Logic:

"Attributes": {
  "Primary": "Site",
  "Name": "Region=Udûn; The Sulfur-deeps; The Under-courts"
}

A candidate card matches if it satisfies the dynamic predicate (e.g. Cirith Gorgor matches Region=Udûn) OR matches any of the literal card titles.

Example B — Compound AND Logic (via Predicate Expansion):

"Attributes": {
  "Primary": "Site",
  "Name": "{Orc.Home}"
}

If Crook-legged Orc is captured as {Orc} and carries Home: Region=Under-deeps && Site!=Dark-hold, candidate cards must be located in the Under-deeps AND must not be a Dark-hold.

Unmet Dependency Handling: If a token references a category or attribute that is absent on the captured card(s), it resolves to an empty string (""). The rule recognizes that the dependency was not met, adds 0 cards, and cleanly hands execution over to the Fallback rule without interrupting generation.

5. Native Save Files (.json) vs. Rule Templates (.json)

Both deck save files and procedural rule sets share the .json extension, but serve distinct roles:

  • Deck Save Files (Deck > Save Deck / Open Deck...): Store an assembled deck instance. Root keys: CurrentDeckTitle, SetList, PoolList, ResourceList, HazardList, SideboardList, and SiteList.
  • Rule Templates (Deck > Generate from Rules...): Declarative instructions used to generate random decks on demand. Root keys: DeckTitle, RuleSetType, and Rules.
