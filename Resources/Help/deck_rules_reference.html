Deck Rules JSON Schema Reference

Procedural deck generation templates are declarative JSON files loaded via Deck > Generate from Rules... (Ctrl+G, or re-run instantly with F5). This reference details all JSON schema elements, properties, data types, default values, multi-card collections, and token interpolation rules.

1. Root Object (DeckGenerationRuleSet)

Property Type Default Description
DeckTitle string "Generated Deck" Default title assigned to the deck. Can be dynamically overridden by a branch choice at runtime.
RuleSetType string "SequentialRules" Execution strategy identifier (reserved for future execution engines).
Version string "1.0" Schema version indicator.
Rules array of objects [] An ordered list of DeckGenerationRule objects evaluated sequentially from top to bottom.

2. Rule Object (DeckGenerationRule)

Property Type Default Description
RuleType string "FilterQuery" Rule mode:
  • "FilterQuery": Standard query that samples matching cards.
  • "RandomChoice" (or "Choice" / "OneOf" / "Or"): Evaluates a weighted random branch from Choices.
Name string "" Descriptive name displayed in generation logs and shortfall notices.
Section string "Resources" Target deck partition: "Pool", "Resources", "Hazards", "Sideboard", or "Sites".
Count integer 1 The total number of card copies requested by this rule. For broad queries, the engine prioritizes distinct card titles (variety-first) before assigning duplicates; for exact title queries (e.g. {"Name": "Marvels Told"}), it adds multiple copies of that specific card up to legal deck limits.
SaveAs string "" Captures all cards successfully selected by this rule into an in-memory variable (e.g. "Leader" or "ExpeditionSites"). If Count is greater than 1, downstream placeholders ({VariableName.Property}) resolve to a deduplicated, semicolon-delimited union set across all captured cards.
Sets array of strings [] Restricts sampling to specific expansion set codes (e.g. ["METW", "MEDM"]). If omitted, defaults to the sets currently checked in the app's Catalog menu.
Attributes dictionary (Attribute: Value) {} Key-value pairs of official card attributes and required values (e.g. {"Race": "Dwarf", "Skill": "Diplomat"}). Supports semicolon OR syntax and variable interpolation.
Categories dictionary (Category: Tag) {} Key-value pairs of custom taxonomy categories and required tags (e.g. {"Faction Bonus": "Wood-elves", "Automatic Attack": "Dragon"}). Supports semicolon OR syntax and variable interpolation.
Fallback object null A nested DeckGenerationRule executed automatically if this rule fails to fulfill its requested Count (due to missing tags, zero matching candidates, or deck uniqueness limits). Inherits the parent's target Section if unspecified.
Choices array of objects [] Used when RuleType is "RandomChoice". Contains weighted branches.

3. Branch Choice Object (DeckGenerationChoice)

Property Type Default Description
Name string "" Branch label recorded in the execution log (e.g. "Dwarf Company").
DeckTitle string "" Optional deck title override applied if this branch is selected.
Weight integer 1 Relative lottery weight. Selection probability equals Weight / Total Weights (e.g., choices weighted 1 and 3 yield 25% and 75% selection chances).
Rules array of objects [] The list of sub-rules executed sequentially if this branch wins the roll.

4. Query & Placeholder Interpolation Rules

A. Semicolon Multi-Value OR Logic

Any string inside Attributes or Categories can contain multiple semicolon-delimited values. A card matches if it satisfies any of the values: 

"Attributes": {
  "Skill": "Warrior; Scout",
  "Secondary": "Major Item; Minor Item"
},
"Categories": {
  "Automatic Attack": "Dragon; Drake"
}

B. Runtime Variable Interpolation (SaveAs → {...})

When a rule captures one or more cards via "SaveAs": "MyVar", downstream rules can dynamically query those cards' properties using bracketed tokens:

Token Syntax Target Source Example Resolved Output (Sample)
{Variable.AttributeName} Official Card Attribute {Leader.Home} "Rivendell"
{Variable.Race} Official Card Attribute {Leader.Race} "Elf"
{Variable.Category:CategoryName} Custom User Taxonomy Tag {Leader.Category:Faction Bonus} "Wood-elves; Elves of Lindon"
Multi-Card Collections & Union Sets: If a variable captures multiple cards (e.g., a rule with "Count": 5 and "SaveAs": "ExpeditionSites"), any token referencing that variable (such as {ExpeditionSites.Category:Automatic Attack} or {ExpeditionSites.Region}) automatically collects the values from all captured cards into a deduplicated, semicolon-delimited string (e.g., "Dragon; Orcs; Trolls; Undead"). Downstream rules evaluate this as an OR query, making it straightforward to generate site-matched hazards or regionally cohesive companies.
Unmet Dependency Handling: If a token references a category or attribute that is absent on the captured card(s), it resolves to an empty string (""). The rule recognizes that the dependency was not met, adds 0 cards, and cleanly hands execution over to the Fallback rule without interrupting generation.

5. Native Save Files (.json) vs. Rule Templates (.json)

Both deck save files and procedural rule sets share the .json extension, but serve distinct roles:

  • Deck Save Files (Deck > Save Deck / Open Deck...): Store an assembled deck instance. Root keys: CurrentDeckTitle, SetList, PoolList, ResourceList, HazardList, SideboardList, and SiteList.
  • Rule Templates (Deck > Generate from Rules...): Declarative instructions used to generate random decks on demand. Root keys: DeckTitle, RuleSetType, and Rules.
