Deck Rules JSON Schema Reference

Procedural deck generation templates are declarative JSON files loaded via Tools > Generate Deck from Rules... (or re-run instantly with F5). This reference details all JSON schema elements, properties, data types, default values, and token interpolation rules.

1. Root Object (DeckGenerationRuleSet)

Property Type Default Description
DeckTitle string "Generated Deck" Default title assigned to the deck. Can be dynamically overridden by a branch choice at runtime.
RuleSetType string "SequentialRules" Execution strategy identifier (reserved for future execution engines).
Version string "1.0" Schema version indicator.
Rules array of objects [] An ordered list of DeckGenerationRule objects evaluated sequentially from top to bottom.

2. Rule Object (DeckGenerationRule)

Property Type Default Description
RuleType string "FilterQuery" Rule mode:
  • "FilterQuery": Standard query that samples matching cards.
  • "RandomChoice" (or "Choice" / "OneOf"): Evaluates a weighted random branch from Choices.
Name string "" Descriptive name displayed in generation logs and shortfall notices.
Section string "Resources" Target deck partition: "Pool", "Resources", "Hazards", "Sideboard", or "Sites".
Count integer 1 The exact number of card copies requested by this rule.
SaveAs string "" Captures cards successfully selected by this rule into an in-memory variable (e.g. "Leader" or "Scout"). Subsequent rules can interpolate their attributes or tags using {VariableName.Property}.
Sets array of strings [] Restricts sampling to specific expansion set codes (e.g. ["METW", "MEDM"]). If omitted, defaults to the sets currently checked in the app's Set menu.
Attributes object (key-value) {} Dictionary of official Cardnum rules criteria (e.g. "Primary", "Race", "Skill", "Name"). Supports semicolon OR syntax and variable interpolation.
Tags object (key-value) {} Dictionary of custom user taxonomy criteria (e.g. "Archetype": "Ring Destruction"). Supports semicolon OR syntax and variable interpolation.
Fallback object null A nested DeckGenerationRule executed automatically if this rule fails to fulfill its requested Count (due to missing tags, zero matching candidates, or deck uniqueness limits). Inherits the parent's target Section if unspecified.
Choices array of objects [] Used when RuleType is "RandomChoice". Contains weighted branches.

3. Branch Choice Object (DeckGenerationChoice)

Property Type Default Description
Name string "" Branch label recorded in the execution log (e.g. "Dwarf Company").
DeckTitle string "" Optional deck title override applied if this branch is selected.
Weight integer 1 Relative lottery weight. Selection probability equals $\frac{\text{Weight}}{\sum \text{Weights}}$.
Rules array of objects [] The list of sub-rules executed sequentially if this branch wins the roll.

4. Query & Placeholder Interpolation Rules

A. Semicolon Multi-Value OR Logic

Any string inside Attributes or Tags can contain multiple semicolon-delimited values. A card matches if it satisfies any of the values: 

"Attributes": {
  "Skill": "Warrior; Scout",
  "Secondary": "Major Item; Minor Item"
}

B. Runtime Variable Interpolation (SaveAs → {...})

When a rule captures a card via "SaveAs": "MyVar", downstream rules can dynamically query that card's properties using bracketed tokens:

Token Syntax Target Source Example Resolved Output
{Variable.AttributeName} Official Card Attribute {Leader.Home} "Rivendell"
{Variable.Race} Official Card Attribute {Leader.Race} "Elf"
{Variable.Tag:CategoryName} Custom User Taxonomy Tag {Leader.Tag:Faction Bonus} "Wood-elves; Silvan Elves"
Unmet Dependency Handling: If a token references a tag or property that is absent on the captured card, it resolves to an empty string (""). The rule recognizes that the requirement was not met and adds 0 cards, cleanly handing execution over to the Fallback rule without crashing.

5. Native Save Files (.json) vs. Rule Templates (.json)

Both deck save files and procedural rule sets share the .json extension, but serve distinct roles:

  • Deck Save Files (File > Save / Open): Store an assembled deck instance. Root keys: CurrentDeckTitle, SetList, PoolList, ResourceList, HazardList, SideboardList, and SiteList.
  • Rule Templates (Tools > Generate Deck): Declarative instructions used to generate random decks on demand. Root keys: DeckTitle, RuleSetType, and Rules.
